## 使用原则

### 1. 技术难点记录是「面试弹药库」

每解决一个**非教程给答案**的问题，就按这个格式记一份：

```
现象 → 排查过程 → 根因 → 方案 → 取舍
```

**为什么这个格式有效**：面试官听项目时，想听的不是「我做了什么功能」，而是「**你遇到问题怎么解决**」。
一份完整的排查记录，能同时证明：技术深度、排查方法论、工程判断力。

### 2. 不要只写「教程教了我什么」

❌ 「我跟着教程实现了 GAS 的属性和技能系统」 —— 这句话没有信息量，谁都能说。

✅ 「我在联机测试时发现动态 GE 的 Tag 复制行为取决于 `ReplicationMode`，
    玩家的 `Mixed` 模式会导致动态 GE 复制失败，我用复制 bool + OnRep 绕开了这个问题」
    —— 这句话证明你有实战能力。

**区别在于：前者是「我学过」，后者是「我解决过」。**

### 3. 记录要留证据

好记录都带这些东西：
- **真实的日志**（不是编的）
- **代码位置**（文件:行号）
- **试过的失败方案**（证明你是排查出来的，不是猜出来的）
- **明确的取舍理由**（证明你有工程判断，不是抄答案）

你现在的两份记录都符合这个标准。
