# 每天 4 小时的推进计划

> 约束：不能全时间投入，需要代肝游戏赚生活费，**每天至少 4 小时**可以给 UE。
> 核心原则：**不断线 > 一次猛干**。

---

## 一、先算账：4h/天 够不够

| 项目 | 时长 | 按 4h/天 |
|---|---|---|
| 剩余教程 | 30h | 约 8 天（纯看） |
| 加上自己动手翻倍 | 60h | 约 15 天 |
| 加一个自己的玩法系统 | +30~60h | +8~15 天 |
| 打包 + 录视频 + 写材料 | +20h | +5 天 |
| **合计** | **110~140h** | **约 1~1.5 个月** |

**结论：4h/天 完全够。** 一个月到一个半月，你就能拿出一份有内容的求职材料。

**你缺的从来不是时间，是稳定性。**

---

## 二、4 小时怎么切（不要 4 小时连续看教程）

**推荐切法（实测有效）：**

| 时段 | 时长 | 做什么 |
|---|---|---|
| **主学习块** | 2.5h | 看教程 + 跟着敲代码。**这是唯一需要"整块时间"的部分** |
| **动手块** | 1h | 自己改点东西 / 复现问题 / 做小实验 |
| **记录块** | 0.5h | 写笔记、写 commit message、记技术难点 |

**为什么这么切**：连续 4 小时看教程，**第 3 小时开始吸收率暴跌**。而「动手 + 记录」反而是在巩固前 2.5 小时学的东西 —— 而且**记录本身就是求职材料**。

---

## 三、铁律：每天必须有 commit

这是**最重要的一条**，重要性超过「学了多少」。

```bash
# 每天结束前，至少一次提交
git add -A
git commit -m "第 X 章：实现了 Y / 排查了 Z 问题"
git push
```

**为什么 commit 记录比学时数重要：**

1. **面试时可以直接展示** —— GitHub 的绿格子是最好的"我在稳定推进"的证据
2. **对抗"自我怀疑"** —— 状态差的时候翻一眼 commit 记录，能看到自己真的在前进
3. **对抗"断线"** —— 一旦断了几天，重启成本极高；有 commit 习惯就不容易断
4. **空白期叙事的物证** —— 你说「从今年年初开始在做项目」，commit 记录就是证明

> **哪怕今天只学懂了 1 行代码，也提交。**
> 「连续 60 天有 commit」比「三天学完 60 小时」有说服力得多。

---

## 四、4 小时不够时的降级预案

总有状态差、代肝忙的日子。这时候**不要硬撑 4 小时，也不要彻底摆烂**：

| 情况 | 降级动作 | 时长 |
|---|---|---|
| 今天很累 | **只写 10 分钟笔记**（复盘昨天学的） | 10min |
| 今天代肝很忙 | **看 30 分钟教程视频**（不动手） | 30min |
| 状态极差 | **只 commit 昨天的笔记** + 读一遍自己的笔记 | 10min |
| **最低限度** | **翻一眼项目 + 提交一个空 commit / 一条笔记** | 3min |

**原则：宁少勿断。** 一天的 100% 不如 30 天的 10%。

**为什么**：技能和项目都是「连续性」资产。断一周回来，要花两天找回上下文；每天 10 分钟保持，成本几乎为零。

---

## 五、一周节奏建议（配合代肝）

```
周一 ~ 周五：主学习块（2.5h）+ 动手（1h）+ 记录（0.5h）
周六：只做记录 + 复盘这一周（1h）
周日：休息 或 补进度
```

**周六的「复盘 + 记录」不要省** —— 这是把「学过的东西」变成「能讲出来的东西」的关键一步。
面试时需要的是**你已经消化过的内容**，不是"我学过"。

---

## 六、进度锚点（防止"学了但没感觉"）

每完成一个里程碑，在 `求职材料/README.md` 里打勾，并写一句话总结：

- [ ] 教程全部学完（第 X 章）
- [ ] 自己的玩法系统完成（设计 + 实现 + 调试）
- [ ] 动态 GE → 资产 GE 重构完成
- [ ] 项目可打包、可联机运行
- [ ] 演示视频录制完成
- [ ] README 写好（技术栈 / 架构 / 已实现功能 / 已知限制）
- [ ] 简历更新

**每一个勾，都是一次"我能做到"的正反馈。** 这对抗长期自学的消耗很重要。

---

## 七、关于代肝这件事

代肝能覆盖生活费，说明你**在自食其力**，这不丢人，也不是"浪费时间"。

但要注意**边界**：

- **代肝收入要稳定到不用再操心**，否则它会不断侵蚀你的 4 小时
- **每天先保 4 小时的 UE**，再用剩余时间代肝（而不是反过来）
- **代肝不要变成"主业"** —— 它的天花板很低，而且不是你的目标方向

> **把代肝看成"临时现金流"，UE 才是"资产积累"。**
> 现金流解决今天的饭，资产解决明天的工作。

---

## 八、一句话总结

> **每天 4 小时 + 每天一个 commit + 每周一次复盘 = 一个半月后你有一份能拿出手的材料。**
>
> 不需要肝到凌晨，不需要完美执行。
> **只需要不断线。**
